# STACK BURGER｜Webサイト制作・実装仕様書

> **架空店舗の営業用ポートフォリオ。** 実在する事業者の公式サイトではありません。記載する設定・価格・営業時間・スタッフ・商品はすべて創作です。店名の重複・商標調査は未実施。制作物には「架空店舗のデモサイト」と明記し、実在する連絡先・レビュー・SNS・地図ピンを創作しないでください。

## 0. Claude Codeへの実装指示
本書を唯一のコンテンツ仕様として、完成度の高いレスポンシブWebサイトを構築する。ポートフォリオの他店舗のテンプレートを流用せず、独自のページ構成・タイポグラフィ・コンポーネントを採用する。Next.js App Router + TypeScript + Tailwind CSSを第一候補とするが、既存プロジェクトがある場合はその構成に合わせる。ビルド・型チェック・リンク/操作テストを行う。初期状態は静的な非公開デモで、注文・決済・顧客情報の送信機能を実装しない。

### コンセプト
**「かぶりつけ、うまさを重ねろ。」**

鉄板に押し付けて香ばしく焼くスマッシュパティ、溶けたチェダーチーズ、シャキシャキの野菜。気取らず、腹いっぱい、おいしいバーガーを楽しむための街のダイナー。学生、友人同士、家族、ひとり客まで入りやすい賑やかな空気を大切にする。

### ブランド人格
元気、豪快、親近感、遊び心。高級店ではなく、こだわりはあるが肩ひじ張らない街のバーガー屋。英語は短いアクセントに限定、日本語の可読性を最優先。

### 店主の架空ストーリー
飲食店のキッチンを経験した20代後半の店主が、旅先で食べたスマッシュバーガーに惚れ込み、会津に帰って開業。肉の香ばしさを最大化する焼き方と、バンズ・ソース・具材のバランスを研究している。産地や調理方法の裏付けが必要な表現（100%国産牛、無添加など）は設定しない。

- スクロール演出で商品の閲覧を妨げない。

## 7. 画像アセットの仕様
すべてAI生成か利用許諾のある素材を使用。第三者店舗の写真、Instagram投稿写真、口コミ写真を無断使用しない。画像の生成時は「写真らしさ」を保ち、文字・ロゴは画像に焼き込まない。
| パス例 | 内容 | 推奨比率 |
|---|---|---|
| `/images/hero-burger.webp` | ダブルチーズバーガー。肉の焼き目・溶けたチーズ・バンズが見える | 4:5または3:4 |
| `/images/classic.webp` | クラシックバーガー単品 | 4:5 |
| `/images/bacon.webp` | ベーコンバーガー単品 | 4:5 |
| `/images/fries.webp` | フライドポテト | 4:5 |
| `/images/griddle.webp` | 熱い鉄板でパティを焼く手元 | 3:2 |
| `/images/interior.webp` | 明るく賑やかな小さなダイナー | 16:9 |

画像がない場合はデザイン崩れを防ぐプレースホルダーを表示。AI生成画像を実店舗の撮影写真と称さない。

## 8. インタラクション仕様
### メニュー切替
- カテゴリ選択（BURGERS / SIDES / DRINKS）はキーボードでも操作可能。
- 商品カードには商品名、説明、税込価格、画像、必要なら架空設定のバッジを表示。
- 切替アニメーションは短く。`aria-selected`等を適切に使用。

### Build Your Stack：注文「シミュレーター」
- ベース商品を1つ選択。初期値はクラシック ¥980。
- トッピングはチェックボックスで複数選択可能。
- セット追加ON/OFF、ポテト大盛りON/OFF（セットありのときのみ）。
- 合計 = ベース商品価格 + トッピング + セット + 対象時の大盛り。
- 合計に税込表示。小数は発生しない。
- リセット可能。キッズ商品を選択した場合セット非対応を明示。
- 完了ボタンは `これは注文ではありません` の説明を表示するだけ。外部送信や個人情報入力なし。

## 9. 技術要件
- コンテンツを `data/site.ts`, `data/menu.ts` 等へ分離し、メニュー変更しやすくする。
- TypeScriptの型を付ける（商品カテゴリ、価格、セット適用可否）。
- 画面幅375px / 768px / 1280px以上で検証。
- Next/Image等による最適化、適切なalt、遅延読み込み。
- メタタイトル `STACK BURGER | 架空バーガーショップ デモサイト`。
- OGPもデモである旨が伝わる説明にする。
- フォーム送信・架空の口コミ・実在しないSNSリンク・誤解を招く構造化データは作らない。
- 静的ホスティング可能な構成を優先。外部APIキー不要。

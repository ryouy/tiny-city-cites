# PÂTISSERIE LUNE — Claude Code 制作仕様書

> **架空店舗のポートフォリオ用デモサイト**。実店舗ではありません。2026年10月13日作成。設定・価格・人物・事業内容はすべて創作です。第三者の商標・写真・ロゴ・SNS投稿を無断使用しないでください。公開時には全ページに「架空店舗の制作デモ」の明示が必要です。

## 1. 制作目的
個人経営の洋菓子店へ提案できる、上質かつ実用的なWebサイトの実例を制作する。ケーキ写真とブランドの世界観を主役にしつつ、商品一覧・サイズ・税込価格・ホールケーキの予約方法が明確に理解できることを重視する。

### 想定する顧客と利用シーン
- 記念日用ホールケーキを探す家族・カップル
- 手土産の焼き菓子を探す20〜50代
- 季節の新作をInstagramで見つけて訪問する顧客
- 営業日・駐車場・受取方法をスマートフォンで確認する顧客

### 店舗の背景・物語
店主はパティスリーで経験を積み、故郷の会津に戻って独立。店名のLUNEはフランス語で「月」。月明かりのように、日々の暮らしの中の小さな特別感を届けたいという思いを込めて名付けた。旬の果物と、素材の味を引き立てる軽やかなクリーム、甘さを抑えた焼き菓子が特徴。**すべて創作であり実在人物の経歴ではない**。

## 5. 情報設計・ページ
- `/` トップ：Hero → ブランドストーリー → 代表ケーキ3点 → Whole Cakes導線 → 焼き菓子 → 店舗案内 → フッター
- `/menu` 商品：`ケーキ / ホール / 焼き菓子` のタブ、各商品カード、税込価格、注意文
- `/order` ホールケーキ案内・予約フローデモ：サイズ・商品・受取日・メッセージプレートの説明。入力フォームは**ブラウザ内デモのみ**で実送信しない。
- `/about` こだわりと架空の店主ストーリー
- `/access` 営業情報・架空エリアの説明。実店舗の住所、地図ピン、電話番号は表示しない。

### ナビゲーション
PC：`LUNE / About / Menu / Whole Cakes / Access`。右端CTA `ホールケーキを見る`。
モバイル：操作しやすいメニュー。固定CTAは必要に応じて `商品を見る` に留める（予約受付を装わない）。

- 方向性：上品、繊細、温かい。過剰な装飾やギラついた金表現は避ける。
- 英字見出しはクラシックなセリフ、日本語本文は可読性の高いゴシック。
- 余白を広く取り、デスクトップで非対称の編集的レイアウトを使用。
- ファーストビューに大きなケーキ写真＋短いコピー。
- 写真のトーン：柔らかな窓光、淡い背景、質感を伝える寄りの写真、俯瞰・断面。
- 動き：短いフェード、控えめなホバー、reduced-motion対応。

## 7. 写真・アセット要件
`/public/images/`に以下を想定する。アセットがない場合は著作権を確認済みの写真または生成した素材を使用し、無関係な写真を商品名に割り当てない。
- `lune-hero.webp` ケーキと焼き菓子のスタイリング、横長
- `lune-shop.webp` 架空店舗の内観または抽象的なイメージ
- `lune-shortcake.webp`, `lune-tart.webp`, `lune-chocolat.webp`
- `lune-whole-cake.webp`, `lune-gift.webp`
- `lune-baker.webp` 手仕事（架空の演出。実在店主の写真は使わない）
- ロゴはテキストベース `PÂTISSERIE LUNE` から実装。商標照合前は架空のブランド表記として扱う。
- 画像はAVIF/WebP、altを適切に付ける。`next/image`等による最適化。

## 8. 機能要件
1. メニューカテゴリのタブ切替（キーボード対応、選択状態表示）
2. ホールケーキの商品・サイズ選択デモと合計価格の表示
3. 受取日セレクター（火水定休・3営業日前を考慮する**デモ用ロジック**。祝日・臨時休業は未対応と明記）
4. 商品予約フォームのモック：氏名、受取希望日、商品、サイズ、メッセージ。フロントエンド検証のみ、送信時は「デモのため予約されません」と表示。情報は外部送信・保存しない。
5. スマホで見やすい営業時間・FAQ
6. 各ページからホームへの戻り方を統一

### 重要な非機能・法務要件
- 本物の決済、在庫、注文、会員登録、メール送信は実装しない。
- サイトヘッダーもしくはファーストビュー付近とフッターに `PORTFOLIO DEMO｜架空店舗の制作事例です` を表示。
- ダミーのSNSリンク、電話リンク、Googleマップピンを設置しない。
- 商品価格はすべて税込、表記を統一。
- 口コミ、受賞歴、食品認証、衛生表示は捏造しない。
- WCAGを意識したコントラスト、フォーカスリング、キーボード操作。
- 画像遅延読み込み、LCPの最適化、360px〜1440pxの画面幅で崩れない。

## 9. 推奨技術構成
- Next.js App Router + TypeScript + Tailwind CSS（既存リポジトリがあればそれを優先）
- 依存関係は最小限。アニメーションライブラリの多用は避ける。
- 商品マスターは `src/data/menu.ts` に集約しUIへ直書きしない。
- コンポーネント例：`SiteHeader`, `Hero`, `SectionHeading`, `ProductCard`, `MenuTabs`, `CakeConfigurator`, `DemoReservationForm`, `SiteFooter`, `DemoNotice`。
- SEO：架空事業につき本番店舗を装う構造化データ（LocalBusiness等）は付けない。`noindex,nofollow` をデモサイト全体に適用。OG画像は独自制作素材。

## 10. 受け入れ基準
- 全メニューの名称・価格が本仕様と一致
- タブ・選択UI・デモフォームが実際に操作できる
- 予約送信が実行されず明示的にその旨を説明
- 営業時間・定休日を表記し、連絡先を捏造していない
- PC/スマホで美しく読みやすい
- alt・見出し階層・キーボード操作・reduced motion対応
- `npm run lint`, `npm run build` が通る（利用プロジェクトに合わせる）
- デモ表記が全ページにあり、本物の営業店舗と誤認されない
